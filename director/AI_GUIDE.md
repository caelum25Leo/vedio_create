# 做片流程

按这一页做片。导演读 `DIRECTOR.md`，衔接做法读 `TECHNIQUE.md`，截帧和合成读 `export.md`。

**画面不由你画。** 用户给的分镜 JS 画 `out/samples/` 里的每一张样帧，样帧的像素谁都不许改。你做的只有两件事：这些样帧按什么顺序、各停多久；以及**相邻两张样帧之间的中间帧**怎么接。风格就是这些样帧本身。

不要用视频生成模型。不要读 `styles/` —— 不查 `STYLE.md`、不开 `DEMO.md`、不搬里面的笔刷、着色器、配色、字体和转场习惯。不要改 `core/`。不要调用 `lemo-opuscar-main` 的 `core/render`、`mux.sh`、配音或拨弦。片子放在仓库的 `films/<name>/`，`<name>` 只用小写字母、数字和连字符。

在代码里重画、简化、"补全"一张样帧，是这套流程最严重的失败：片子会变成对用户画稿的火柴人模仿。样帧不对就报告用户，不要替他改画。

配音（`core/tts/`）和拨弦（`core/audio/pluck.py`）先不做。片子需要旁白时，用用户给的录音；没有录音就不要旁白，在 `TREATMENT.md` 里写明。

## 1. 问清一次

先读 `films/<name>/brief.md`。四个字段决定你能不能开工：`brief:drawing`（主 JS，在 `films/<name>/storyboard/` 里，连同它 import 的模块和引用的图片字体一起拷在那里）、`brief:materials`（输入界面「读取 JS」生成的报告：推定的 A/B/C/D 模式、画幅、帧率、镜头表、缺哪些依赖，D 模式还会写推镜怎么接、锚点在哪、哪些模块要先给 `wx` 打桩）、`brief:shots`（推镜顺序，一行镜头 id）、`brief:motion`（主体接续关键帧 `t x y action`）。`brief:drawing` 是空的就停下来向用户要 JS，没有它无从下手。报告是猜的，仍然要自己打开 JS 看一遍：它导出几个分镜、每镜几张样帧、画布多大、import 了什么。仓库里 `films/earth-to-fukushima/` 是一支**已经走完全流程的 D 模式例子**（brief + 四格分镜 JS + `camera.mjs` 量出来写进 `camera.json` 的取景参数 + `shim.mjs`/`film.js`/`shotplan.json`/`export.mjs` + `out/samples/` 的样帧与 `out/inbetweens/` 的三段推进接片条 + `TREATMENT.md`/`CREDITS.md` + 成片的 mp4）。碰到同类型的 JS：brief 先看，`TREATMENT.md` §4 其次 —— 那一节写的是这个模式里真正会咬人的三件事。brief 里的 `style` 字段是旧流程留下的，忽略。

用户已经说清的不要再问。还缺的，合成一条消息问完，然后用合理默认补上，不再追问。

- 主题：讲给谁，一句话要说清的事，结尾停住的那句。
- 故事走向：开端、转折、结尾，以及结尾停住的那句 —— 内容从 brief 来，也从样帧画了什么来。样帧撑不起 brief 要的那条弧线时，告诉用户，不要自己加戏。
- 片长和画幅：帧率和尺寸取 JS 的画布（brief 的 `size` 是从 JS 读出来的，读不到就是空的）；JS 没写就 24 fps。D 模式（一格一个模块）的 JS 里往往既没有画幅也没有帧率，`size` 是用户在界面上填的，以它为准，别拿模块内部精灵的边长当画幅。默认 30–60 秒，由 JS 提供的分镜组成。JS 的分镜比片长装得下多，就说出来并问砍哪几个，不要默默砍。尺寸和 brief 对不上就问哪个为准，绝不重采样、不拉伸画稿。
- 衔接方式：分镜之间靠图层视差、变形、光流，还是只靠镜头运动。这是你唯一的质量杠杆，方案见 §2。
- 用户自己的音乐、照片、logo。有就优先用，但只能放在 JS 已经为它画了位置的地方。
- 要不要先看分镜。默认不要，直接做到样帧。

一个主角，一个目标，一次转折。开头 3 秒里就要发生事情。

## 2. 先出样帧，再写方案

顺序和以前相反：**先跑 `node export.mjs --sample`，让 JS 自己把样帧画出来**，看过这些图之后才写 `films/<name>/TREATMENT.md`。没读过 JS、没看过样帧之前写出来的方案，全是猜的。

`TREATMENT.md` 里写：

1. 三个可选的**衔接方案**，各几行，然后选定一个，并写为什么。例如：(a) 相邻样帧分层视差 + 跟主体，镜头连续；(b) 样帧之间网格变形，不设镜头；(c) 样帧整幅不动，运动全交给镜头运动和设计的转场。指明选的是哪个、代价是什么。
2. 分镜清单：JS 提供的每一镜、对应哪几个样帧文件、这张样帧画的是什么。只有一张样帧的镜头标成**静帧镜**（只能靠镜头动，不能变形）。
3. 衔接表：每一对相邻样帧一行 —— 方法（图层 / 变形 / 光流 / 镜头 / 转场）、要跟踪的锚点（两张图里同一个部件）、中间帧跑多少帧、失败时退回什么。**图层 / 变形 / 光流 这三样靠 `tools/join.py`，仓库里还没实现（`TECHNIQUE.md` §13.2 是设计稿）**，所以现在能选的是镜头和转场；D 模式另加一行「重投影」，写清取景怎么插、掩模在哪一段换、私有图层怎么叠。
4. 一句话故事，以及开端、转折、结尾。
5. 对标作品：学它的什么（剪辑节奏、两个构图之间怎么走、A 画留多少在 B 画里、气口在哪），不搬它的样子（样子已经由样帧定了）。
6. 镜头表：每一镜的样帧、取景、镜头运动、秒数、为什么这样拍。
7. 按秒的节拍，以及配乐重音落在哪一次衔接上。
8. 每一段的环境声、主要音效、音乐状态。
9. 字幕和标题的位置：从样帧自己的空白带来定（那一张哪里没画东西、没写字），不要照搬一套字版样式。

然后从第 2、3、6、7 条写出 `shotplan.json`：它是画面、声音和检查共同读的那一条时间轴（`TECHNIQUE.md` §3）。字幕停留按 `DIRECTOR.md` §7 的秒数规则。

## 3. 一条时间轴

`films/<name>/shotplan.json` 是画面、音效和字幕的共同时间：镜头、每镜的样帧、每一对样帧之间的衔接方法、锚点、事件、字幕，全在里面。镜头首尾相接。不要另写一份 `timeline.js` 把同样的数再存一遍。字幕烧进画面，停留至少 1.8 秒，并且不短于念完再加 0.6 秒。

## 4. 画面

一个 `films/<name>/index.html`，满足 `export.md`：

- `window.DURATION`、`window.FPS`、`window.renderAt(t)`、`window.assetsReady`
- 同一个 `t` 画出同一帧。不用 `Date.now()`，不用没有种子的 `Math.random()`。
- 预览只在 `?preview=1` 时用 `requestAnimationFrame`。

`renderAt(t)` **只做合成，不做绘制**：读样帧 → 上镜头 → 做衔接 → 压字幕。JS 和片子之间隔一层 `shim.mjs`（`TECHNIQUE.md` §2），片文件夹里只有 `shim.mjs` 可以碰 JS，而且只从外面调它，绝不重画。

用户的 JS 和它加载的一切已经在 `films/<name>/storyboard/` 里（输入界面拷的），**不改一行**。import 装不上就告诉用户缺哪个路径。中间帧的像素只能来自两张样帧：允许视差用的边缘延展、遮罩修补，以及片子自己的字幕 / 标题层；不允许从代码里画出样帧里没有的东西。锚点从样帧上量出来，不要凭感觉填（`TECHNIQUE.md` §13）。

D 模式（一格一个模块）另加三句，都是例片上量出来的（`TECHNIQUE.md` §2 末尾、`films/earth-to-fukushima/TREATMENT.md` §4）：① 取景参数写**全精度**进 `camera.json`，模块里只要有从坐标取小数位的噪声，四舍五入就会让整幅对不上；② 两套掩模覆盖同一片地面时，中途硬换会看得见地跳，要在接点末段渐变，并在 `u=1` 完全落到目的地自己的掩模上；③ 某一格里私有图层插不进去，只能抠出来按比例缩放叠，透明度给 `min(1,s)`、画幅边按 `(1-s)` 羽化，`s=1` 时两者都归零才不会破回环。

**JS 是小程序里的那一份**（用 `wx.createCanvas()` / `wx.createCanvasContext()` + `draw()`）时，不要叫用户改成浏览器写法：`tools/preview/wx-shim.js` 垫两代接口，`node tools/preview/build-preview.mjs films/<name>` 把模块和它 import 的一切、加上 `shotplan.json` 这类数据打成一个**独立 `preview.html`**（普通 `<script>`，不用 module，`file://` 双击就开，不用起服务）。页里两个视图：**成片**走片子自己的 `renderAt(t)`，和导出的 mp4 同一帧；**小程序**直接调模块默认导出的 `draw(ctx, stage)`，等于手机上那一屏，画布尺寸可填（750×1334 / 375×667 / 成片尺寸）。加 `--verify` 会用 msedge 无头开一次，报「有没有错、哪些 `wx` API 没垫上、每一格画没画出东西」；加 `--stills` 则把 `storyboard/` 里**每个 JS** 各渲一张 png 到 `out/preview/`，并给每个 JS 留一份同名 `.txt` —— 画得出写尺寸和像素统计，画不出写原因，不允许出现没人解释的空白。输入界面底部有「预览」按钮，开一个窗口：左边一个 JS 一个按钮，点下去看 `--stills` 渲好的那张静帧（网页不嵌进 Qt 窗口，Chromium 45 认不了这些 JS）；要看动的就点窗口里「在浏览器打开这一格」，它只把深链交给 Edge。「读取 JS」只读，不再生成预览也不弹浏览器。跟用户说的时候叫按钮名就行，不用他记命令行。细节见 `TECHNIQUE.md` §2 末。

## 5. 两道关：样帧、衔接条

样帧和中间帧分别放在 `films/<name>/out/samples/` 和 `out/inbetweens/`。`--sample` / `--inbetween` 按这次的时间点写文件，名字对不上的旧图会留在目录里，新旧就会混在一起。

每次出图之前，先删掉那个目录里全部图片（png、jpg、jpeg、webp），再按 `export.md` 跑命令。导出脚本在写入新图之前做这件事。不要删 `out/<name>.mp4`，也不要删这两个目录以外的图。

**第一关 —— 样帧。** `node export.mjs --sample` 只跑用户的 JS。逐张打开检查：分镜数和 JS 对得上、每张画完整（不是空帧、没清干净、边缘没被切掉）、文件名和你要排的镜头一一对应。JS 报错、画不出、某一镜取不到，就报告用户 —— 你不修画，也不用自己画的替身顶上去。不想来回跑命令行，就在 `preview.html` 里点「逐格样帧」看第一关、点「接片条 + 回环数字」看第二关：那上面印的回环数字和 `--inbetween` 算的是同一个（例片实测六端点 SSIM 1.0000、均差 0.00）。

**第二关 —— 衔接条。** `shotplan.json` 写好后跑 `node export.mjs --inbetween`，逐条看：主角是沿路径走的还是瞬移；有没有重影、双线、撕边；有没有哪一帧出现了两张样帧里都没有的东西（那就是在重画）；在样帧自己那个时间点取到的帧是否还和样帧一致（SSIM ≥ 0.97）。不对就改方案或改方法，重跑这条衔接条。D 模式没有变形，前三条基本不会犯，改看这三条：推进中段是清楚的还是放大糊开的；中途有没有一下跳变（掩模换了）；有没有哪一帧像贴了张硬边矩形卡（图层没羽化）。回环数字由 `film.js` 自己算、由导出脚本随接片条打印，不依赖 `tools/join.py`。两道关都过了才渲全片。

用户要求分镜时，把样帧按镜头顺序交给用户，每张标镜号、取景、秒数、字幕，外加你选的衔接方案每个衔接一行 —— 图是他自己的画，这一步确认的是你的**方案**，不是画面。停下来等确认。用户没要求就不要停。

## 6. 声音

音效和配乐对齐 `shotplan.json` 的 `EV`，写成 `films/<name>/out/mix.wav`，再交给 `export.md` 贴上画面。没有这条 wav 时，导出只垫一条等长静音 —— 用户没给录音、没要音乐，就老实垫静音并在 `TREATMENT.md` 里写明，**不要在导出脚本里自己生成一段配乐**（`tools/trailer/export.mjs` 里的 `writeScore` 是那支预告片自己的事）。这一节跟画面无关：D 模式全程不需要 Python，`uv` 只为声音服务。每个衔接都要有声音：切点、变形的划过、落到新样帧上的那一下。

本机用 `uv` 跑 Python，不要假设系统里有 `python`。在 `director/` 下执行，这样能 `import core.audio`。

程序音效用 `core/audio/sfx.py`（48 kHz）。碰撞、划过、脚步、闷击、叮、点燃、心跳、对讲机染色、压缩和限幅都在这里。`add(buf, sound, t, gain, pan)` 放进立体声。调用顺序固定，结果就固定。

配乐用 `core/audio/sampler.py`。采样在 `director/core/audio/instruments/`。这个目录不存在或是空的，就停下来告诉用户，不要改去 `lemo-opuscar-main` 找，也不要擅自下载采样包。乐器不看风格库，按样帧给人的感觉（年代、重量、冷暖）挑，理由写进 `TREATMENT.md`，全片一套。依赖是 numpy、scipy、soundfile、soxr：

```powershell
cd d:\code\vedio_create\director
uv run --with numpy --with scipy --with soundfile --with soxr python -c "from core.audio import sampler as S; print(S.instruments('strings')[:8])"
```

乐谱事件是 `(时间, 乐器, 音高, 时长, 力度, 声像)`。乐器名和许可证见 `core/audio/INSTRUMENTS.md`。用过的乐器写入片子的 `CREDITS`。

音乐在对白和关键音效下面让出约 10 dB。响度大约 −14 LUFS，在 wav 里做好，不要靠导出时重编码来压。

## 7. 导出全片

样帧、衔接条和 `out/mix.wav` 都就绪后，按 `export.md` 跑 `node export.mjs`。成品是 `films/<name>/out/<name>.mp4`：页面尺寸、`FPS`、时长等于 `DURATION`、一条音轨。

交付前确认 `out/samples/` 里每一张样帧在成片中原样出现过：在它自己的时间点那一帧和 PNG 对得上、满分辨率、没拉伸、除了全片统一的那一道调色之外没被改过。`poster.jpg` 从这些样帧里挑最像海报的一张，可以裁尺寸，不要往里画东西。

交付时告诉用户片子路径。第三方采样、字体列在 `CREDITS`，并加一行说明分镜画稿和样帧来自用户的 `<文件>`（版权由用户自己确认）。片子说了事实（真实地点、地图、量出来的数字）就再交一份 `FACTS.md`：每一条要么给来源，要么给复现它的命令 —— 例片 `films/earth-to-fukushima/FACTS.md` 就是这么写的（`TECHNIQUE.md` §11）。
